# GAMUT 0.3.0 Scope

- **Status:** Planned
- **Milestone:** [0.3.0](https://github.com/eharquin/gamut/milestone/4)
- **Previous release:** [0.2.0](0.2.0.md)

GAMUT 0.3.0 turns the local graph library into a browsable library panel with
personal graphs and shipped examples, both in folders, adds folders and
comment rows to the expression panel, makes the coordinate tuple a PGA point,
and moves the largest blocks out of `App.tsx` before these interface additions
land. It also closes the pending acceptance of 0.2.0.

This document records the planned scope. It becomes the release notes when
0.3.0 is published.

## Design decisions

- **Coordinate tuples.** The tuple is resolved by the active algebra, never by
  a hidden `vector` call. In PGA(2), `(x, y, w)` is a homogeneous point, so
  `(x, y, 0)` is an ideal point; a triple is never a line, which keeps
  `line(a, b, c)`. No short aliases such as `p(…)` or `l(…)` are added (#180).
- **One folder model.** Expression folders (#83), library folders (#267) and
  the directories of the `.zip` archive (#268) share one folder model and,
  where possible, one folder component. Folders are structural only: they do
  not override appearance or position and do not change the canvas draw order,
  which stays the expression order. An expression folder's collapsed state is
  stored in the document and travels with it; collapsing is not an undo entry.
- **Three storage formats, compatible with 0.2.0 where it can run.**
  - The canonical document moves to format version 8, for expression folders
    (#83) and `ViewState.display.valuesVisible` (#191). Earlier documents
    migrate on load; 0.2.0 cannot open a version 8 document, which the release
    notes state.
  - The library index keeps version 1: entries gain an optional `folder`
    field, which 0.2.0 already preserves, and empty folders use a separate
    key. A 0.2.0 tab still open, or a rollback, keeps every graph (#267).
  - The `.zip` archive has a versioned manifest and documented limits (#268).
- **Single source for showcases.** Each algebra's showcase is an example of the
  Examples library; the first run and the algebra switch load it (#217, #270).
- **Hidden values are a document setting** (#191), so a teacher can share a
  document whose values are hidden. A hidden value is announced as hidden.
- **Comment text.** Comment rows (#187) render a restricted Markdown subset:
  bold and italic with delimiters that leave `a*b*c` and `x_1` literal, inline
  code, backslash escapes, and links limited to `http`, `https` and `mailto`.
  No raw HTML and no `innerHTML`, since shared scene links display text written
  by someone else.
- **Archive import is untrusted input** (#268): bounded size, entry count and
  decompression, rejected unsafe paths, duplicates, encrypted or ZIP64 entries
  and CRC mismatches, and no storage writes in a temporary session.
- **Interface lands outside `App.tsx`.** New panels, menus and rows are
  separate components and hooks (#274).

## Acceptance

0.3.0 is published under the [project workflow](../project-workflow.md#6-publish-an-accepted-release)
when:

- every issue above is closed and the 0.3.0 acceptance record (#272) is
  complete, as is the 0.2.0 PGA(2) acceptance record (#192);
- `npm run verify` passes on the release commit;
- regression fixtures open unchanged: 0.1.0 and 0.2.0 (version 7) documents,
  0.2.0 scene links, and a 0.2.0 library snapshot from browser storage;
- an index written by 0.3.0 keeps every graph under the 0.2.0 library rules;
- a test fails if a shipped example is not in the current canonical format or
  opens with diagnostics;
- the package version, CHANGELOG, citation metadata and these release notes
  are updated together.

The language version does not change: tuples and comment rows only make valid
sources that were errors before.
